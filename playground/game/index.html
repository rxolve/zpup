A game drawn as JSON

Image models can't draw the same thing twice. Ask for a character from the front, then from the side, and you get two different characters.

Here an AI model did not draw pictures. It wrote each object once, as a small 3D scene in JSON. Zpup drew that scene from every side. So the person below is the same person in all 8 directions and all 16 poses.

Chop trees, carry the logs, build the cabin. Move: arrow keys or WASD, or click where to go. Chop: stand by a tree. Build: walk to the site with logs on your back.

One scene, eight directions

These are not eight drawings. They are one scene, turned eight times.

A new motion is a few lines

The model wrote the person once, with six poses for walking. Later, a second session got the same scene and added the axe and the load. It did not draw the person again. A pose is a short list of changes, mostly joint angles. This is the whole pose for the moment the axe hits: 


  

    The tree falls the same way. The cabin has five building stages, and they are five poses of
    one scene.
  


  
The sheets

  

    Each sheet is one PNG with a frame list next to it. A row is a direction and a column is a
    pose. The scene and the poses are the JSON the model wrote.
  

  


  
What this is not

  

    It is not much of a game. There is one cabin and a clock. It is here to show the pictures at
    work. The pictures are simple: flat colors, no textures and no perspective. Each pose is a
    still picture, and the page shows them one after another. I wrote the rules, the paths and
    the timing by hand. I also wrote how the logs stack on the person's back: it is the log's
    own picture, drawn several times.
  


  
Make your own

  
Zpup comes with an MCP server. In Claude Code:

  
claude mcp add zpup -- npx -y @zpup/mcp

  

    Then ask the model for an object and a sprite sheet of it. The code and the reference are at
    github.com/rxolve/zpup, under the MIT license.
