A game drawn as JSON

Chop trees, carry the logs, build the cabin. Every picture here was drawn by an AI model with Zpup: it wrote each object once, as a small 3D scene in JSON, and Zpup drew that scene from every side. The pictures of one object cannot disagree with each other, because they are one object.

Move: arrow keys or WASD, or click where to go. Chop: stand by a tree. Build: walk up to the site with logs on your back.

A new motion is a few lines

The person was written once, with a walk of six poses. The axe and the load came later, in a second session that was given the scene and asked for more poses, not for a new drawing. A pose is a short list of changes to the scene, mostly joint angles, and each pose is drawn from the same eight sides. This is the whole of the pose where the axe has struck: 


  

    The tree falls and the cabin goes up in the same way: the stages of the cabin are five poses
    of one scene.
  


  
The sheets

  

    Each is one PNG with a frame list beside it, as render_sprites writes them, with
    a row for each direction and a column for each pose. The scene and the poses are the JSON the
    model wrote.
  

  


  
What this is not

  

    It is not much of a game: one cabin, and a clock. It is here to show the pictures at work.
    The motion is in steps: each pose is a still picture, and this page plays them in turn.
    Nothing is drawn between two poses. There are no textures and no perspective, and the look is
    one flat style. The rules, the paths and the timing were written by hand, and so was the
    stacking of the logs on the person's back, which is the log's own sheet drawn several times.
  


  
Make your own

  
Zpup comes with an MCP server. In Claude Code:

  
claude mcp add zpup -- npx -y @zpup/mcp

  

    Then ask the model for an object and a sprite sheet of it. The code and the reference are at
    github.com/rxolve/zpup, under the MIT license.
